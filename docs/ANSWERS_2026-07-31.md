## Break — the seven death-triggers

**1.** Refund — but not a flat "the die's gold value." See #38: per missing
die, 450g each (a save down two dice gets compensated for two).

**2.** RULED: the player's own die returns to the lane immediately, they
stay at 6. The lane persists as fixed table infrastructure; only the
specific die occupying it can be destroyed. Cost of breaking a borrowed
die = cost of breaking any die, never inflated to a whole seat.

**3.** RULED: `d._preserved`, a boolean directly on the die object.

**4.** NOT MINE — Code's call, zero design stakes either way.

**5.** Belongs with the Fair Trade/Trade items; same ruling (#2) applies.

**6.** RULED: FROM the rival, a real deduction, not just a mirrored gain —
see #8 for the corrected mechanism this actually resolves into.

**7.** Acknowledged — needs its own harness pass, now higher-priority given
#8's fix makes the row's magnitude genuinely different from before.

**8.** RULED, with a mechanism fix, not just a policy call: the row steals
the opponent's MOST RECENTLY COMPLETED turn's bank (0 if they busted it),
added to the player and subtracted from the opponent's running total.
Needs a new field (`G._oLastBank`, written the instant the opponent's turn
resolves) — `G._oUnbanked` as currently read is structurally broken by
turn alternation and can't be patched into correctness, it needs replacing.

**9.** RULED: align to Falling Star's existing ordering — counts normally,
advances turnNum, refreshes Quicksilver. A cap-bypassing "extra turn" is
exactly the shape of hole this project exists to close; don't let a newer
mechanic quietly disagree with an established, safe one.

**10.** RULED: confirmed intentional. Brass/Crystal/Ruby/jade3 are all
retired with no path back into circulation — no new rows owed. "Lucky" is
a naming flag, not a family, shouldn't need one either.

**11.** RULED: keep as shipped (claims/replaces the interrupted roll). The
alternate reading (genuine second roll, bust-escape included) would
recreate a second Ward — exactly the redundant-systems shape this project
keeps closing elsewhere.

## Badges — Kindred and Still Waters

**32.** RULED, in full:
- Tithe: 2x gold (already shipped, sim-confirmed).
- Ward: two-thirds save instead of half (NOT two arms per turn — that
  reopens the stacking problem the loadout cap exists to prevent).
- Snare: halves twice on the SAME next-turn shot (NOT an extended window
  — extending it risks recreating the 97.7%-fires problem the shortened
  window was built to fix).
- Snuff/Fog: extends to two turns (NOT two lanes — a much bigger power
  spike than "double" should mean, given Snuff's baseline already tested
  strong on its own).
- Break/Trade: NEVER double, explicitly excluded from the whitelist, not
  left ambiguous. Nothing coherent exists for either.

**33.** Leaning NO, not a full ruling. Still Waters is uniquely build-
neutering next to the other seven tells (it switches off something built,
they tax gold/tempo/lane-value). That severity reads as earned walking
into Aldric specifically, less so as an unpredictable patron encounter.
Closer to a feel call — flip it if playtesting disagrees.

**34.** CONFIRMED: good, keep it. Drops the mutual claim, stays in voice,
matches the standing rule that barks carry flavor while tooltips carry
precise mechanics.

**35.** RULED: yes, the ring should mark worked/hushed dice BEFORE the
tap. Same "visible cost at decision time, never a surprise after"
principle behind every other targeting fix in this project. A Break spent
on a silenced payout must be a knowing choice, never a trap.

**36.** Acknowledged, all three already flagged as needing validation —
this confirms none are done yet. First three items whenever harness work
resumes.

## Cut enchants and the universal icon rule

**42.** CONFIRMED: narrow reading is correct, REJECTED stands. The wide
reading hands every icon-holder a free, unconditional discard — the same
"unconditional free option" shape this project has closed everywhere else
it's appeared (old Silver, the 2/3/4/6 branding exploit).

**43.** REVISED after actually checking the history rather than re-
asserting confidence. "Half Measure" traces to the July 9 session — three
weeks before the six-family card system existed — as `measure_twice` in
an old boss's card pool. It does not appear anywhere in the July 11 or
July 31 sessions, the two where the entire current family-card system was
built from scratch. That's suspicious on its own, but real engineering
history complicates a clean "it's dead" call: July 9's code already
carries the exact bug this question describes, in a comment fixing how
kept dice get counted across a turn ("Half Measure fired for NPC even
with >3 dice"). That confirms the counter (`totalCommitted` /
`G._oTurnDiceCommitted`) was built to count KEPT dice specifically, not
scored dice or points — real evidence for the original answer, not just
a consistency argument.
Two separate things follow: (a) IF Half Measure is still a live,
obtainable card, the answer stands with actual evidence behind it now —
yes, an icon die should count, since the counter's own designed purpose
is commitment, not score. (b) WHETHER it's still live at all is now the
bigger, genuinely open question — it may be counting dice for a card no
current boss or draft pool can actually offer, in which case #43 is moot,
not answered. Can't verify (b) from transcript history alone; needs a
direct check against the current build's card pools before either half
of this is treated as settled.

**44.** RULED: yes, a mixed selection should name the firing enchant too
("+500 · TITHE"). Same "make the cost visible before commitment"
principle as #35, just its cheaper sibling.

**49-51 — dialogue placement, answered as one question with three parts,
since the right answer splits by CONTENT TYPE rather than picking one
venue for everything:**

- **In-match trait reactions (busts, big banks) → the existing DLG hooks
  (#49). This is DONE** — built as the 72-line trait-reaction pool,
  additive to the existing 64-call-site system, never replacing it. A
  named or generic patron's trait colors the existing bark; the existing
  generic bark remains the floor if nothing else applies.
- **King ensemble + town gossip → the ROOM SCREEN, as overheard chatter
  (#50).** This is a better fit than my earlier guess — these lines were
  never written as things said TO the player, they're patrons talking
  among themselves. Ambient room chatter is the correct register for
  content nobody is personally directing at you, and it sits at a point
  in the flow (before a peek is even opened) that can't compete with the
  peek's "2-second read" job, solving that concern a different way than
  originally proposed.
- **Named-patron personal/backstory lines → the WIN/LOSS screen**, per my
  earlier recommendation, now narrowed to just this content type rather
  than everything. This is the moment right after actually playing that
  specific person — the natural point for a stage-counter increment and a
  relationship to feel like it deepened because of something that
  happened, not because a sheet was glanced at.
- **#51 ("nowhere yet, until the ladders are written") is now stale** for
  the same reason as #47 — the content this was waiting on has since been
  written in volume.
